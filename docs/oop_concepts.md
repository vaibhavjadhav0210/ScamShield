# OOP Concepts in ScamShield

This document maps every Object-Oriented Programming (OOP) concept demonstrated in **ScamShield** to its exact file, class, and method.

| OOP Concept | Where It Is Implemented | How It Is Used |
|---|---|---|
| **1. Abstraction** | `scamshield/detectors/base.py` (`Detector`), `scamshield/explain/explainer.py` (`Explainer`), `scamshield/models/message.py` (`Message`) | All three inherit from `abc.ABC` and define `@abstractmethod` contracts (`detect()`, `explain()`, `get_context_features()`), hiding implementation details behind clean interfaces. |
| **2. Inheritance** | `scamshield/models/message.py` (`SMS`, `WhatsApp`, `CallTranscript` -> `Message`); `scamshield/detectors/` (`RuleDetector`, `MLDetector`, `HybridDetector` -> `Detector`); `scamshield/explain/explainer.py` (`TemplateExplainer`, `LLMExplainer` -> `Explainer`) | Subclasses reuse shared base behavior (e.g. `Message._base_signals()`, `Detector.name`) and specialize behavior for each channel or algorithm. |
| **3. Polymorphism** | `scamshield/service.py` (`ScamShieldService.analyze`), `scamshield/models/message.py` (`get_context_features`), `scamshield/detectors/` (`detect`) | `ScamShieldService` calls `self._detector.detect(message)` and `self._explainer.explain(message, result)` uniformly regardless of which concrete detector or explainer is active. Each `Message` subclass overrides `get_context_features()`. |
| **4. Encapsulation** | `scamshield/models/message.py` (`Message._text`, `Message._sender`, `@dataclass(frozen=True) DetectionResult`); `scamshield/detectors/ml.py` (`MLDetector._pipeline`, `_is_trained`); `scamshield/detectors/rule.py` (`RuleDetector._rules`, `Rule`) | Internal state is stored in private (`_`) attributes with read-only `@property` getters and constructor validation. `DetectionResult` is an immutable frozen dataclass. |
| **5. Composition** | `scamshield/detectors/hybrid.py` (`HybridDetector` HAS-A `MLDetector` and `RuleDetector`); `scamshield/service.py` (`ScamShieldService` HAS-A `Detector`, `Explainer`, and `HistoryLog`); `scamshield/explain/explainer.py` (`LLMExplainer` HAS-A `TemplateExplainer`) | Complex behavior is built by combining independent objects rather than deep inheritance hierarchies. |
| **6. Strategy Pattern** | `scamshield/service.py` (`ScamShieldService.set_detector()`, `set_explainer()`) | Allows swapping `RuleDetector`, `MLDetector`, and `HybridDetector` (or `TemplateExplainer` and `LLMExplainer`) at runtime in `app.py` and `evaluate.py`. |
| **7. Factory Pattern** | `scamshield/models/message.py` (`MessageFactory.create(msg_type, text, **kwargs)`) | Centralizes instantiation of `SMS`, `WhatsApp`, and `CallTranscript` from string identifiers. |
| **8. Custom Exceptions** | `scamshield/exceptions.py` (`ScamShieldError`, `EmptyMessageError`, `ModelNotTrainedError`, `InvalidMessageTypeError`) | Provides domain-specific error handling for empty inputs, untrained ML models, and invalid channel types. |
